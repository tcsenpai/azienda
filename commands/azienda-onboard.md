## Environment detection

!`bash ${CLAUDE_PLUGIN_ROOT}/scripts/onboard.sh detect`

## What to do now

Above is the real state of the environment (mycelium present or not, project
already initialized or not, tracking already configured or not). Conduct the
**task tracking** onboarding for this project:

1. **If tracking is already configured** (the output above says so): report it
   to the founder in one line and ask if they want to reconfigure it. If not, stop here.

2. **Ask the founder** using the interactive question tool.
   The main choice is the tracking backend, with this default:
   - **mycelium** if `myc` is PRESENT (recommended: it's the first-class
     support, see `myc --help` / the AGENTS.md generated by `myc prime-agents`);
   - **vault** (folder `./.claude/azienda/vault/` with `TASKS.md`) if `myc` is
     ABSENT, or if the founder explicitly prefers lightweight tracking
     without dependencies.
   Present the default already highlighted based on the environment. Don't force
   mycelium if it's not installed — offer the vault as a natural alternative.

3. **Execute the choice** (only one of the two). Use the ABSOLUTE path of the
   script that the `detect` output above printed (the `bash /…/onboard.sh
   …` lines). Do NOT use `${CLAUDE_PLUGIN_ROOT}`: in your Bash calls it's empty and the
   path wouldn't resolve.
   - mycelium → `bash …/onboard.sh init-mycelium` (runs `myc init` +
     `myc prime-agents` in the project), then `bash …/onboard.sh set-tracking mycelium`.
   - vault → `bash …/onboard.sh init-vault`, then `bash …/onboard.sh set-tracking vault`.

4. **Record it in the policies**: open `./.claude/azienda/policies.md` (created by
   `/azienda on`) and note in the workflow section WHICH tracking the project
   uses and how (e.g. "tasks via `myc task create ...`" or "tasks in
   `./.claude/azienda/vault/TASKS.md`"). If the policies don't exist yet,
   remind the founder to run `/azienda on` first.

5. **Confirm** to the founder in a few lines: chosen backend, what was
   initialized, where tasks live from now on. From here on, in azienda
   mode, track work with the backend configured in the shared file
   `./.claude/azienda/tracking`.

## (Optional) Repo assessment → policies

After configuring tracking, ASK the founder if they want you to run a
repository assessment to populate this project's policies. It's
**optional**: if they say no, skip it entirely and don't touch `policies.md`.

If they say yes (and ONLY if they consented):

1. Gather the repo facts by running, via Bash, `assess.sh` NOW from the SAME
   `scripts/` folder as `onboard.sh` (use the ABSOLUTE path printed
   by the `detect` output above and substitute `onboard.sh`→`assess.sh`; do NOT use
   `${CLAUDE_PLUGIN_ROOT}`, empty in your Bash calls).
   Don't run it before consent: the assessment is optional and must not run
   if the founder said no.
2. From those facts deduce stack, project nature, and services. Then **ask
   targeted questions** to the founder for the policy sections the assessment
   touches: stack and package manager, services/infra, how tests run and
   what must be green to say "done", any constraints (prod DB, secrets), specific bans.
3. Write to `./.claude/azienda/policies.md` **only** the values the founder
   confirms. Don't invent constraints unsupported by the facts. Preserve the rest
   of the file (it's manually editable by the founder: don't overwrite it wholesale,
   integrate the relevant sections).

## (Optional) Manual policy editing

The policies are a normal Markdown file at `./.claude/azienda/policies.md`: the
founder can edit them by hand whenever they want, you re-read them each session. At
the end of onboarding, offer — **without forcing it** — to open them and refine them together
now. If the founder prefers to edit them alone later, just point them to the
path and stop.
